一、项目概述与技术栈
================================================================================

  本系统是一个基于 Spring Boot + Vue3 的在线协作编辑系统，支持多人实时
  协作编辑文档，核心功能包括：文档管理、实时协作编辑、版本控制、评论系统、
  权限管理、系统监控等。

  ◆ 技术栈总览：

  ┌──────────────────────────────────────────────────────────────┐
  │ 层级           │ 技术选型                                    │
  ├──────────────────────────────────────────────────────────────┤
  │ 前端框架       │ Vue 3.4+（Composition API + script setup）  │
  │ 前端构建       │ Vite 5.4                                    │
  │ UI 组件库      │ Element Plus 2.7                            │
  │ 富文本编辑器   │ Quill 1.3（Delta 格式操作）                 │
  │ 图表库         │ ECharts 6 + vue-echarts 8                   │
  │ 状态管理       │ Pinia 2.1                                   │
  │ 前端路由       │ Vue Router 4.3（History 模式）              │
  │ HTTP 客户端    │ Axios 1.7                                   │
  │ 实时通信       │ 原生 WebSocket                              │
  ├──────────────────────────────────────────────────────────────┤
  │ 后端框架       │ Spring Boot 2.7.18                          │
  │ 编程语言       │ Java 17                                     │
  │ ORM 框架       │ MyBatis-Plus 3.5.5                          │
  │ 数据库         │ MySQL 8.0                                   │
  │ 认证方案       │ Spring Security + JWT（jjwt 0.9.1）         │
  │ WebSocket      │ Spring WebSocket（TextWebSocketHandler）    │
  │ 工具库         │ Lombok、Hutool 5.8.25                       │
  │ 密码加密       │ BCrypt（Spring Security 内置）              │
  └──────────────────────────────────────────────────────────────┘

  ◆ 系统架构图（文字版）：

  ┌───────────┐     HTTP/WS      ┌───────────┐        ┌─────────┐
  │  浏览器    │ ◄──────────────► │ Vite Dev  │◄─Proxy─│ Spring  │

三、数据库设计（8张表详解）
================================================================================

  数据库名：collab_edit
  字符集：utf8mb4（支持 emoji 和中文）
  排序规则：utf8mb4_unicode_ci

  ◆ 表 1：sys_user（用户表）

  存储系统中所有注册用户的基本信息和认证数据。

  字段名          | 类型          | 约束               | 说明
  ─────────────────────────────────────────────────────────────────
  id              | BIGINT        | PK, AUTO_INCREMENT | 用户唯一ID
  username        | VARCHAR(50)   | NOT NULL, UNIQUE   | 登录用户名
  password        | VARCHAR(255)  | NOT NULL           | BCrypt加密密码
  nickname        | VARCHAR(50)   |                    | 显示昵称
  email           | VARCHAR(100)  |                    | 邮箱地址
  avatar          | VARCHAR(255)  |                    | 头像URL
  role            | VARCHAR(20)   | DEFAULT 'USER'     | 角色：USER/DOC_ADMIN/SYS_ADMIN
  status          | TINYINT       | DEFAULT 1          | 状态：0禁用 1正常
  last_login_time | DATETIME      |                    | 最后登录时间
  created_at      | DATETIME      | DEFAULT NOW()      | 创建时间
  updated_at      | DATETIME      | DEFAULT NOW()      | 更新时间（自动更新）

  角色说明：
  - USER：普通用户，可创建/编辑文档、查看在线用户、添加评论、版本对比/回滚
  - DOC_ADMIN：文档管理员，额外可设置权限、管理成员、转移所有权
  - SYS_ADMIN：系统管理员，额外可查看系统配置、审计日志、资源监控

  ◆ 表 2：document（文档表）

  存储所有文档的元数据和内容。

  字段名          | 类型          | 约束               | 说明
  ─────────────────────────────────────────────────────────────────
  id              | BIGINT        | PK, AUTO_INCREMENT | 文档唯一ID
  title           | VARCHAR(200)  | NOT NULL           | 文档标题
  content         | LONGTEXT      |                    | 文档内容（Quill Delta JSON）
  owner_id        | BIGINT        | FK → sys_user.id   | 创建者/所有者ID
  status          | TINYINT       | DEFAULT 1          | 0已删除 1正常 2归档
  is_public       | TINYINT       | DEFAULT 0          | 0私有 1公开
  current_version | INT           | DEFAULT 1          | 当前版本号
  doc_size        | BIGINT        | DEFAULT 0          | 文档大小（字节）
  created_at      | DATETIME      | DEFAULT NOW()      | 创建时间
  updated_at      | DATETIME      | DEFAULT NOW()      | 更新时间

  说明：删除文档为软删除（status=0），不会物理删除数据行。

  ◆ 表 3：document_member（文档成员表）

  存储文档的协作成员及其权限。

  字段名          | 类型          | 约束               | 说明
  ─────────────────────────────────────────────────────────────────
  id              | BIGINT        | PK, AUTO_INCREMENT | 记录ID
  document_id     | BIGINT        | FK → document.id   | 文档ID
  user_id         | BIGINT        | FK → sys_user.id   | 用户ID
  permission      | VARCHAR(20)   | DEFAULT 'VIEW'     | VIEW只读/EDIT可编辑/ADMIN管理员
  invited_by      | BIGINT        |                    | 邀请人ID
  created_at      | DATETIME      | DEFAULT NOW()      | 加入时间
  updated_at      | DATETIME      | DEFAULT NOW()      | 更新时间

  联合唯一约束：(document_id, user_id)，防止重复添加成员。

  ◆ 表 4：document_version（文档版本表）

  存储文档的历史版本快照，支持版本对比和回滚。

  字段名          | 类型          | 约束               | 说明
  ─────────────────────────────────────────────────────────────────
  id              | BIGINT        | PK, AUTO_INCREMENT | 版本记录ID
  document_id     | BIGINT        | FK → document.id   | 所属文档ID
  version_number  | INT           | NOT NULL           | 版本号（递增）
  content         | LONGTEXT      |                    | 该版本的完整内容快照
  content_hash    | VARCHAR(64)   |                    | 内容哈希（用于校验）
  operator_id     | BIGINT        | FK → sys_user.id   | 保存版本的用户ID
  change_summary  | VARCHAR(500)  |                    | 版本变更说明
  doc_size        | BIGINT        | DEFAULT 0          | 该版本文档大小
  created_at      | DATETIME      | DEFAULT NOW()      | 创建时间

  ◆ 表 5：operation_log（操作日志表）

  存储文档编辑过程中的每个原子操作（OT 操作），用于协作冲突处理。

  字段名          | 类型          | 约束               | 说明
  ─────────────────────────────────────────────────────────────────
  id              | BIGINT        | PK, AUTO_INCREMENT | 操作ID
  document_id     | BIGINT        | FK → document.id   | 文档ID
  user_id         | BIGINT        | NOT NULL           | 操作用户ID
  operation_type  | VARCHAR(30)   | NOT NULL           | INSERT/DELETE/RETAIN/FORMAT
  operation_data  | TEXT          |                    | 操作详细数据（JSON格式）
  base_version    | INT           | NOT NULL           | 基于的版本号
  created_at      | DATETIME      | DEFAULT NOW()      | 操作时间

  ◆ 表 6：document_comment（文档评论表）

  存储文档中的评论，支持嵌套回复和标记解决。

  字段名          | 类型          | 约束               | 说明
  ─────────────────────────────────────────────────────────────────
  id              | BIGINT        | PK, AUTO_INCREMENT | 评论ID
  document_id     | BIGINT        | FK → document.id   | 所属文档ID
  user_id         | BIGINT        | FK → sys_user.id   | 评论者ID
  content         | TEXT          | NOT NULL           | 评论内容
  parent_id       | BIGINT        |                    | 父评论ID（用于回复）
  position_info   | VARCHAR(200)  |                    | 关联文档位置（JSON）
  resolved        | TINYINT       | DEFAULT 0          | 0未解决 1已解决
  created_at      | DATETIME      | DEFAULT NOW()      | 创建时间
  updated_at      | DATETIME      | DEFAULT NOW()      | 更新时间

  ◆ 表 7：audit_log（系统审计日志表）

  记录系统中所有重要操作，用于安全审计和问题追踪。

  字段名          | 类型          | 约束               | 说明
  ─────────────────────────────────────────────────────────────────
  id              | BIGINT        | PK, AUTO_INCREMENT | 日志ID
  user_id         | BIGINT        |                    | 操作用户ID
  username        | VARCHAR(50)   |                    | 操作用户名
  action          | VARCHAR(50)   | NOT NULL           | 动作：LOGIN/CREATE/UPDATE/DELETE等
  target_type     | VARCHAR(30)   |                    | 目标类型：DOCUMENT/USER/SYSTEM
  target_id       | BIGINT        |                    | 目标对象ID
  detail          | TEXT          |                    | 操作详情
  ip_address      | VARCHAR(50)   |                    | 操作者IP地址
  created_at      | DATETIME      | DEFAULT NOW()      | 操作时间

  ◆ 表 8：system_config（系统配置表）

  存储可动态调整的系统参数。

  字段名          | 类型          | 约束               | 说明
  ─────────────────────────────────────────────────────────────────
  id              | BIGINT        | PK, AUTO_INCREMENT | 配置ID
  config_key      | VARCHAR(100)  | NOT NULL, UNIQUE   | 配置键名
  config_value    | VARCHAR(500)  |                    | 配置值
  description     | VARCHAR(200)  |                    | 配置说明
  updated_by      | BIGINT        |                    | 最后修改人ID
  created_at      | DATETIME      | DEFAULT NOW()      | 创建时间
  updated_at      | DATETIME      | DEFAULT NOW()      | 更新时间

  初始配置项：
  - max_storage_per_user：单用户存储上限（默认 100MB = 104857600 字节）
  - version_retention_days：版本保留天数（默认 90 天）
  - max_doc_size：单文档大小上限（默认 10MB = 10485760 字节）
  - max_collaborators：单文档最大协作人数（默认 20 人）
  - websocket_heartbeat_interval：WebSocket 心跳间隔（默认 30 秒）

------------------------------------------------------------------------
4.1 项目入口与配置
------------------------------------------------------------------------

  ◆ CollabApplication.java
  Spring Boot 应用启动入口类，使用 @SpringBootApplication 注解，
  通过 @MapperScan("com.collab.mapper") 自动扫描 MyBatis Mapper 接口。

  ◆ application.yml
  核心配置文件，定义了：
  - 服务端口：8080
  - MySQL 数据库连接信息：localhost:3306/collab_edit
  - MyBatis-Plus 配置：驼峰命名映射、SQL 日志、自增主键策略
  - JWT 配置：密钥和过期时间（24小时 = 86400000毫秒）

  ◆ MyBatisPlusConfig.java
  配置 MyBatis-Plus 分页插件 MybatisPlusInterceptor 和自动填充处理器，
  自动为 createdAt 和 updatedAt 字段填充当前时间。

  ◆ CorsConfig.java
  配置跨域资源共享（CORS），允许前端开发服务器（localhost:5173）
  访问后端 API。

------------------------------------------------------------------------
4.2 统一响应与异常处理
------------------------------------------------------------------------

  ◆ Result.java
  统一 API 响应格式封装：
  - code：状态码（200 成功，其他为错误码）
  - message：提示消息
  - data：业务数据
  提供静态方法：success()、success(data)、fail(message)、fail(code, message)

  ◆ PageResult.java
  分页结果封装：
  - records：当前页数据列表
  - total：总记录数
  - size：每页大小
  - current：当前页码
  - pages：总页数

  ◆ GlobalExceptionHandler.java
  使用 @RestControllerAdvice 注解，全局捕获异常并返回统一格式响应，
  处理 BusinessException（业务异常）和 Exception（未知异常）。

------------------------------------------------------------------------
4.3 认证与安全模块
------------------------------------------------------------------------

  ◆ SecurityConfig.java
  Spring Security 配置：
  - 禁用 CSRF（前后端分离项目）
  - 会话策略设为 STATELESS（无状态，使用 JWT）
  - 放行路径：/api/auth/**（登录注册）、/ws/**（WebSocket）
  - 其他所有请求需要认证
  - 在 UsernamePasswordAuthenticationFilter 之前插入 JwtAuthenticationFilter

  ◆ JwtUtil.java
  JWT 令牌工具类：
  - generateToken(userId, username, role)：生成 JWT 令牌
    包含 claims：userId、username、role、过期时间
  - getUserIdFromToken(token)：从令牌解析用户ID
  - getUsernameFromToken(token)：从令牌解析用户名
  - validateToken(token)：验证令牌有效性

  ◆ JwtAuthenticationFilter.java
  JWT 认证过滤器（OncePerRequestFilter）：
  - 从 HTTP Header 中提取 Authorization: Bearer <token>
  - 调用 JwtUtil 验证令牌
  - 验证通过后将用户信息设置到 SecurityContext 中
  - 后续 Controller 可通过 SecurityContextHolder 获取当前用户ID

4.10 OT 算法引擎
------------------------------------------------------------------------

  ◆ OTEngine.java
  实现操作转换（Operational Transformation）算法：

  核心概念：
  - 当多个用户同时编辑同一文档时，各自的操作可能会冲突
  - OT 算法通过转换操作，使所有用户最终看到一致的文档内容

  主要方法：
  - transform(op1, op2)：将两个并发操作进行转换，
    返回转换后的操作对，保证操作应用后内容一致
  - compose(op1, op2)：将两个连续操作合并为一个操作

  │    支持：标题、加粗、斜体、       │ ├─ 评论标签页 ─────────┤

  └───────────────────────────────────┴────────────────────────┘

  核心逻辑：

  1. 文档加载（onMounted）：
     → fetchDocument(docId) 获取文档数据
     → initEditor() 初始化 Quill 编辑器
     → 解析 JSON content → quill.setContents(delta)
     → connectWebSocket() 建立实时连接
     → 并行加载成员/评论/版本数据

  2. 实时保存：
     → quill.on('text-change') 监听编辑事件
     → 仅 source === 'user' 时触发（排除 API 导入的变更）
     → 防抖 2 秒后调用 updateDocument() 保存到数据库
     → 同时通过 WebSocket 发送操作给其他在线用户

  3. WebSocket 协作：
     → 连接 /ws/collaborate?docId=X&token=XXX
     → 接收 operation 事件 → quill.updateContents(ops, 'api')
     → 接收 userJoin/userLeave/sync → 更新在线用户头像列表
     → 发送 cursor 事件 → 同步光标位置

  4. 弹窗功能：
     → 添加成员弹窗：搜索用户 → 选择 → 设置权限 → 邀请
     → 保存版本弹窗：输入版本说明 → 创建版本快照

七、核心技术原理

------------------------------------------------------------------------
7.1 JWT 认证流程
------------------------------------------------------------------------

  1. 用户登录 → 后端验证密码 → 生成 JWT Token（包含 userId, username, role）
  2. 前端将 Token 保存到 localStorage
  3. 后续每次请求，Axios 拦截器自动在 Header 中添加：Authorization: Bearer <token>
  4. 后端 JwtAuthenticationFilter 拦截请求 → 解析并验证 Token
     → 将用户信息注入 SecurityContext
  5. Controller 通过 SecurityContextHolder 获取当前用户 ID
  6. Token 有效期 24 小时，过期后前端会收到 401 → 自动跳转登录页

------------------------------------------------------------------------
7.2 OT（操作转换）算法原理
------------------------------------------------------------------------

  场景：用户 A 和用户 B 同时编辑同一段文字 "Hello"

  用户 A 在位置 5 插入 " World"  → 操作 Op_A: insert(5, " World")
  用户 B 在位置 0 插入 "Say "    → 操作 Op_B: insert(0, "Say ")

  如果直接按顺序执行，结果会不一致。

  OT 转换过程：
  - A 收到 Op_B 后，需要转换自己的操作位置：
    因为 B 在 A 之前插入了 4 个字符，A 的操作位置需要 +4
    转换后 Op_A' = insert(9, " World")
  - 最终所有用户看到相同结果："Say Hello World"

  本系统通过 WebSocket 实时广播操作，OTEngine 负责操作转换。

------------------------------------------------------------------------
7.3 混合存储模式（操作日志 + 快照）
------------------------------------------------------------------------

  ◆ 操作日志存储：
  每次编辑操作（插入/删除/格式化）都记录到 operation_log 表。
  优点：精确记录每步操作，可回放编辑历史。
  缺点：随时间积累，数据量大。

  ◆ 快照存储：
  用户手动保存版本时，将当前文档完整内容保存到 document_version 表。
  优点：快速加载文档（直接读取快照），版本对比方便。
  缺点：每个版本都是完整副本，占用存储空间。

  ◆ 混合策略：
  - 日常编辑通过操作日志实时同步
  - 关键节点通过快照保存版本
  - 通过系统配置 version_retention_days 控制版本保留期限
  - 平衡了实时性（操作日志）和存储效率（定期快照）

------------------------------------------------------------------------
7.4 WebSocket 心跳与重连
------------------------------------------------------------------------

  ◆ 心跳机制：
  客户端每 30 秒发送 ping 消息（JSON 格式 {type: "ping"}），
  如果一段时间内没有收到 pong 响应，认为连接已断开。

  ◆ 自动重连：
  连接异常关闭时（onclose/onerror），客户端会自动尝试重新连接。
  重连间隔逐步增大（避免服务器压力），重连后重新同步文档状态。

  ◆ 在线用户管理：
  - 连接时：后端将用户加入文档的在线集合 → 广播 userJoin（附带最新在线列表）
  - 断开时：后端将用户移出在线集合 → 广播 userLeave（附带最新在线列表）
  - 前端收到事件后更新在线用户头像显示

------------------------------------------------------------------------
7.5 密码安全方案
------------------------------------------------------------------------

  使用 BCrypt 算法加密存储密码：
  - BCrypt 是一种自适应哈希函数，内置盐值（salt），每次加密结果不同
  - 即使数据库泄露，攻击者也无法反推出原始密码
  - Spring Security 内置 BCryptPasswordEncoder：
    - 注册时：passwordEncoder.encode(plainPassword) → 生成密文
    - 登录时：passwordEncoder.matches(plainPassword, hashedPassword) → 比对
